# Архитектура

UnixGram Changelog разделяет обнаружение и публикацию. Источник никогда не пишет в канал напрямую.

```text
источник → нормализация → fingerprint → очередь review → редактор → Telegram
                                  ↘ история SQLite ↗
```

## Контуры

1. **Sources** получают изменения и возвращают `Detection` с записью, доказательством и уверенностью.
2. **Ingestion** изолирует ошибки источников и сохраняет новые записи в очередь.
3. **Repository** вычисляет устойчивый SHA-256 fingerprint и блокирует повторные записи.
4. **Review** показывает редактору готовый Telegram-предпросмотр.
5. **Publisher** отправляет одобренную запись и сохраняет ID сообщения.

## Что автоматизируется

- получение и нормализация данных;
- первичная категория по правилам источника;
- защита от дублей;
- составление предпросмотра;
- сохранение истории.

## Что подтверждает человек

- смысл и точность описания;
- корректность категории;
- достаточность доказательств;
- необходимость изображения;
- момент публикации.

Полная автопубликация допустима позже только для источников с формальным контрактом и высоким уровнем доверия. По умолчанию проект работает в review-first режиме.

## Масштабирование

`ChangeSource` задаёт минимальный асинхронный протокол. Новый источник не знает о Telegram и SQLite. При росте нагрузки SQLite можно заменить PostgreSQL, а сбор вынести в отдельные процессы без изменения модели публикации.
